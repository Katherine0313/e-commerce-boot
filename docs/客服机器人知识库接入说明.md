# 客服机器人知识库接入说明

## 1. 背景与目标

微信侧不允许小程序接入大模型，因此客服机器人改为**纯知识库问答**：

- 所有回答来自 `docs/QandA.xlsx`（132 条），不调用任何大模型、不做二次生成
- 用户要人工时直接转人工，其余问题必须命中知识库
- 未命中不编答案，统一兜底并引导人工客服
- 小程序接口契约不变，只新增 `contact` / `matched` 字段

## 2. 整体链路

```
小程序客服页
  └─ POST /api/agent/chat（带用户 JWT）
       └─ 网关 gateway:8080  (/api/agent/** → AI_SERVICE_URL)
            └─ FastAPI ai-service:8000
                 ├─ 人工 / 投诉意图 → 直接返回转人工话术
                 ├─ kb_qa 检索（MySQL，60 秒缓存）
                 │    ├─ 命中 → 返回答案原文
                 │    └─ 未命中 → 兜底话术 + contact=true，并写 kb_miss
                 └─ 不访问任何大模型
```

## 3. 数据

### 3.1 表结构

建表脚本：[20261105_kb.sql](20261105_kb.sql)

| 表 | 用途 |
|---|---|
| `kb_qa` | 知识库主表，一行一条标准问法；`(category, question)` 唯一 |
| `kb_miss` | 未命中记录，供运营补库，不参与检索 |

`kb_qa` 关键字段：`category` 分类、`question` 标准问法、`answer` 答案原文（直接返回）、`keywords` 逗号分隔关键词、`priority` 同分排序、`status` 启停、`hit_count` 命中次数。

### 3.2 数据源与导入

唯一数据源：[QandA.xlsx](QandA.xlsx)，单 Sheet `qa`，四列：分类 / 问题 / 答案 / 关键词。

```bash
# 在 recommender-python 目录执行
.venv/Scripts/python scripts/import_kb.py            # 建表 + 导入
.venv/Scripts/python scripts/import_kb.py --dry-run  # 只统计，不写库
```

幂等：按 `(分类, 问题)` upsert，只更新答案与关键词，不新增重复行、不清零 `hit_count`。运营改完 Excel 重新跑一次，最多 60 秒（缓存 TTL）生效。

## 4. 检索与打分

纯规则，见 `recommender-python/app/kb/matcher.py`。

1. 归一化：全角转半角、转小写、去掉标点/空白/表情（`normalize.py`）
2. 打分：

| 规则 | 得分 |
|---|---|
| 用户问法与标准问题完全一致 | 100 |
| 一方包含另一方 | 92 |
| 关键词命中：2 字 / 3 字及以上 | +55 / +65，累计上限 100 |
| 字二元组 Dice 相似度 | ×60 |
| 上一轮命中的分类 | +8 |

3. 阈值 55，低于阈值视为未命中；同分时 `priority` 大优先，再优先命中次数少的
4. 上一轮分类存在 Redis `agent:kb:lastcat:{sessionId}`，2 小时过期，支持“先说退款，再问多久到账”这类追问

所有条目在内存中缓存 60 秒；Redis 或 MySQL 挂掉时沿用旧缓存，不影响回答。

## 5. 意图与文案

### 5.1 意图拦截（不走检索）

| 意图 | 触发词 | 返回 |
|---|---|---|
| 人工 | 人工、真人、转人工、人工客服、找客服、人工服务、转客服 | 转人工话术 + `contact=true` |
| 投诉 | 投诉、差评、举报、纠纷、维权、骗子、欺诈 | 售后专员话术 + `contact=true` |

### 5.2 固定文案

- 转人工：`好的，正在为您转接人工客服，请稍等～`
- 投诉：`非常抱歉给您带来不好的体验，我马上为您转接售后专员跟进，请稍等。`
- 未命中：`不好意思，这个我不太确定，您可以直接联系人工客服，他们会更快帮您解决。`（`contact=true`、`feedback=true`）
- 服务异常/超时：`抱歉，这边暂时有点忙，请稍后再试，或点「人工客服」直接联系我们。`
- 命中知识库时**不加任何收尾话术**，气泡保持干净

### 6.3 接口契约

```json
// POST /api/agent/chat
// 请求
{"message": "什么时候发货", "sessionId": "xxx", "scene": "customer-service"}
// 响应
{"success": true, "data": {"reply": "...", "contact": false, "feedback": false, "matched": true}}
```

`/api/agent/chat/stream` 保留兼容（SSE，`data: <纯文本>`），小程序默认不再调用。鉴权与限流不变：`Authorization: Bearer <type=user 的 JWT>`。

## 8. 验收结果

本地直连 `uvicorn` + 真实 MySQL 验证：

- 30 条正样本（改写问法）：命中 29 条，命中率 96.7%
- 10 条无关问题（老板是谁、天气、写诗、下载抖音等）：0 条误命中
- 接口验证：命中返回答案且 `matched=true`；未命中返回兜底且 `contact=true`；`转人工` / `我要投诉` 直接转人工；无 Token 返回 401；SSE 正常分块

已知缺口：`有质量问题怎么办` 这类问题当前知识库没有对应条目，会走兜底转人工。补库时在 Excel 增加一行即可。

## 9. 运营

- 看 `kb_miss` 最近记录，按高频问题补 Excel，再跑导入脚本
- 命中率目标 ≥ 80%；低于目标优先补“售后 / 物流 / 下单支付”三类
- 关键词不宜过宽（如单独的“推荐”“手机”“微信”），容易误命中无关问题
- 每条问答的 `keywords` 建议同时包含 2 字核心词与 4 字具体说法

## 10. 注意事项

- `QandA.xlsx` 目前未被 git 跟踪，建议纳入版本管理或定期备份
- 修改 Excel 后务必重新导入，否则线上仍是旧数据（缓存 60 秒内生效）
- 知识库答案即用户看到的最终文案，不要写 Markdown、不要写“请联系大模型”之类话术
- 小程序 `BASE_URL`：开发 `http://127.0.0.1:8080`，生产 `https://api.jiemids.com`
