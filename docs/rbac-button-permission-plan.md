# RBAC 按钮权限方案（可见但不可操作）

> 生成日期：2026-11-04
> 适用：`e-commerce` 后台管理前端 + `e-commerce-boot` 各服务后端 + `admin_menu` 权限数据

---

## 一、要解决的问题

现状有两类不一致：

1. **按钮直接消失**：部分页面用 `v-if="hasPermi(...)"` 或业务判断把按钮从 DOM 移除。只读角色看到的操作列是空的，列宽塌陷，界面像坏了一样。
2. **按钮没有权限码**：有的按钮（订单查看/删除、售后审核/删除、Banner 编辑）根本没挂权限指令，任何能进页面的人都能点。
3. **一个权限码被多个按钮共用**：售后「审核」和「删除」都用 `aftersale:aftersale:audit`，无法配置「可审核、不可删除」。

目标：遵循 RBAC，**页面按权限决定能否进入，按钮按权限决定能否操作**。

---

## 二、设计原则

| 层级 | 无权限时的表现 | 原因 |
|---|---|---|
| 菜单 / 路由 | 不显示入口，直接访问返回 403 | 没有页面权限，进去也全是 403，隐藏更合理 |
| **写操作按钮** | 外观正常（不置灰），点击时弹出「无权限，无法执行该操作」 | 界面完整，所有人都能看到按钮存在 |
| **只读按钮** | 不加权限标识，有页面权限即可使用 | 不写库，无需控制 |
| 接口 | 返回 403「无权访问该功能」 | 前端提示只是体验，后端才是最终防线 |

配套规则：

- **判断标准只有一个：是否改动数据库。** 新增、修改、删除、审核、上下架、改价、调整库存、发放、重置密码等写操作，必须挂权限标识；查看、详情、筛选、刷新、翻页等只读操作不加。
- **一个写按钮 = 一条 F 类型菜单 = 一个权限码**，不允许两个按钮共用同一个码。
- 权限码格式沿用现有三段式：`模块:资源:动作`，如 `order:order:remove`、`aftersale:aftersale:audit`。
- 只读角色 = 勾选页面的 `:list` 权限，**不勾任何 F 按钮行**。
- 业务状态判断（如「仅未发货才显示发货按钮」）继续用 `v-if`，与权限无关。

---

## 三、当前实现

### 3.1 前端指令

`src/directives/permission.js`

```js
function applyIfNoPermission(el, perm) {
  if (!perm || hasPermi(perm)) return
  if (el.__permGuarded) return
  el.__permGuarded = true
  el.addEventListener('click', (e) => {
    e.preventDefault()
    e.stopPropagation()
    message.warning('无权限，无法执行该操作')
  }, true)
}
```

要点：

- 按钮外观与有权限时完全一致，不置灰、不 disabled。
- 点击时拦截冒泡并弹 Ant Design 提示，用户明确知道「有这个按钮，但没权限」。
- 不删除节点，只加一次监听，`mounted` / `updated` 都做幂等处理。
- 后端仍是最终防线，绕过前端直接调接口会 403。

用法：

```html
<a-button v-permission="'order:order:remove'">删除</a-button>
```

### 3.2 后端校验

- 管理端接口统一在 `PermissionInterceptor` 中校验 `@RequirePerm("xxx")`。
- `admin` 超级管理员按角色放行，不依赖菜单行。
- 前端置灰不是安全边界，直接调接口仍会被 403。

### 3.3 数据模型

`admin_menu` 字段：

| 字段 | 说明 |
|---|---|
| `menu_type` | `M` 目录 / `C` 页面 / `F` 按钮 |
| `parent_id` | F 行挂在对应的 C 页面下 |
| `perms` | 权限码，角色通过 `admin_role_menu` 关联 |
| `visible` | 菜单是否显示，仅对 M/C 有意义，F 行固定 1 |

只读角色的授权数据形态：

```
角色 → 页面 C 行（如 503 Banner管理 business:banner:list）
     → 不勾 541 Banner编辑 business:banner:edit 等 F 行
```

## 六、验收标准

1. 只读角色（销售）登录：
   - 侧边栏只显示已授权页面；
   - 所有操作按钮外观正常，点击弹出「无权限，无法执行该操作」；
   - 手动调接口返回 403。
2. 管理员登录：全部按钮正常可用。
3. 配置「可审核不可删除」的角色：审核正常，点击删除提示无权限，后端删除接口 403。
4. 页面列宽与按钮数量对所有角色一致，不出现操作列空洞。

---

## 七、风险与注意事项

1. **菜单仍然隐藏**：这是有意设计，不是遗漏。只读角色不需要看无权页面。
2. **禁用态可能被绕过**：前端禁用只影响普通用户操作；安全依赖后端 `@RequirePerm`，不得只做前端。
3. **历史角色数据**：拆分权限码后，原共用码的角色默认不带新码，需要人工补勾，避免误放大权限。
4. **业务条件与权限条件要分开**：`v-if` 只用于状态，权限一律用 `v-permission`，便于审计。
